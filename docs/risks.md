# Risk Register

Tracks identified risks to the project. Update when new threats, design gaps or dependency concerns are found. Risks that lead to architectural choices should also get an entry in [DECISIONS_LOG.md](DECISIONS_LOG.md).

| ID | Risk | Severity | Likelihood | Mitigation | Status | Date added |
|----|------|----------|------------|------------|--------|------------|
| R-001 | Indirect prompt injection via untrusted content (web, email, PDF) causes agent to execute harmful actions | Critical | High | Taint tracking, Level 3+ lockout while tainted data in context, red-team suite (SECURITY.md §4) | Open — design phase | 2026-11-22 |
| R-002 | Malicious or compromised skill bypasses permission model | Critical | Medium | Signed packages, permission declaration, sandboxed execution, static analysis (ARCHITECTURE.md §8) | Open — design phase | 2026-11-22 |
| R-003 | Model produces plausible but incorrect tool calls that pass schema validation | High | High | verify() on every tool reads real system state; never trust model's claim of success (ARCHITECTURE.md §4) | Open — design phase | 2026-11-22 |
| R-004 | Remote-control channel compromised or replayed | Critical | Low | E2E encryption (Noise/mTLS), no inbound ports, short-lived sessions, replay protection, device revocation (ARCHITECTURE.md §7) | Open — design phase | 2026-11-22 |
| R-005 | Secret data exfiltrated to cloud model | Critical | Medium | Sensitivity labels (public/personal/secret), policyd enforces which model sees which data, default-deny egress (ARCHITECTURE.md §6, SECURITY.md §6–7) | Open — design phase | 2026-11-22 |
| R-006 | Python `policyd` runs on the same host as the daemon, so a local attacker with the daemon's privileges could read the policyd auth file / socket and forge policy decisions (same-host trust boundary is weaker than a separate user/VM) | High | Medium | Auth file mode 0600, socket in a state dir only the owner can read, no network listener (Unix socket only); Phase 1 documents this limit and recommends running `policyd` as a separate OS user / in a container in production (SPEC §5.2 sandbox option). A Rust `policyd` does not fix this by itself — the boundary is the OS user, not the language. | Open — implemented with mitigations, human review required | 2026-11-23 |
| R-007 | `run_command` (Level 3) can execute arbitrary binaries inside the token scope; an approval granted for one benign command could be replayed for a different command if approvals are scoped too broadly | High | Medium | Approvals are scoped to (token_id, tool_name) with a short expiry (600s default) and are denied while tainted; `run_command` blocks sudo/su/doas and `rm` as argv[0]. Approval scope should be narrowed to (tool + argument hash) in Phase 2 — recorded here, not silently widened. | Open — implemented with mitigations, human review required | 2026-11-23 |
| R-008 | Audit log hash chain detects tampering only if the verifier runs; an attacker who can write the log can also rewrite the whole chain from scratch (no external anchor) | Medium | Low | Hash chain + append-only file; Phase 1 `audit verify` detects in-place edits. External anchoring (signed checkpoints, remote copy) is deferred to a later phase and must be added before audit logs are relied on for forensics. | Open | 2026-11-23 |

| R-009 | `cli/_fallback.py` (933 lines) duplicates the policy engine and tool registry so the CLI can run without the real modules; two policy implementations can diverge, and the fallback runs in-process (weaker isolation than `policyd`) | Medium | Low | Fallback activates only when the real `policy/`/`tools/`/`core/` modules are absent, which never happens in this repo; it is labelled in code. Remove it in Phase 2 once packaging guarantees the real modules are installed — do not extend it. | Open | 2026-11-23 |

Phase 1 status (2026-11-23): R-001 is mitigated in code by taint tracking (Level 3+ locked while tainted) and the red-team suite in `evals/redteam.py`; R-003 is mitigated by `verify()` on every tool. Both still require human review of `policy/` before merge.
