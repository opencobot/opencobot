# Risk Register

Tracks identified risks to the project. Update when new threats, design gaps or dependency concerns are found. Risks that lead to architectural choices should also get an entry in [DECISIONS_LOG.md](DECISIONS_LOG.md).

| ID | Risk | Severity | Likelihood | Mitigation | Status | Date added |

| R-001 | Indirect prompt injection via untrusted content (web, email, PDF) causes agent to execute harmful actions | Critical | High | Taint tracking, Level 3+ lockout while tainted data in context, red-team suite (SECURITY.md §4) | Open — design phase | 2026-11-22 |
| R-002 | Malicious or compromised skill bypasses permission model | Critical | Medium | Signed packages, permission declaration, sandboxed execution, static analysis (ARCHITECTURE.md §8) | Open — design phase | 2026-11-22 |
| R-003 | Model produces plausible but incorrect tool calls that pass schema validation | High | High | verify() on every tool reads real system state; never trust model's claim of success (ARCHITECTURE.md §4) | Open — design phase | 2026-11-22 |

| R-005 | Secret data exfiltrated to cloud model | Critical | Medium | Sensitivity labels (public/personal/secret), policyd enforces which model sees which data, default-deny egress (ARCHITECTURE.md §6, SECURITY.md §6–7) | Open — design phase | 2026-11-22 |
| R-006 | Python `policyd` runs on the same host as the daemon, so a local attacker with the daemon's privileges could read the policyd auth file / socket and forge policy decisions (same-host trust boundary is weaker than a separate user/VM) | High | Medium | State dir is 0700 and audit log, approvals, auth secrets and both Unix sockets are 0600, tightened on startup by the policy engine, `policyd` and the daemon (fail loudly if a path cannot be tightened); `opencobot doctor` reports the permission bits and warns honestly that this is a same-user boundary, not a real OS boundary; README documents running `policyd` as a separate OS user with exact commands. Residual: a real OS boundary still requires that separate user/container — the boundary is the OS user, not the language (a Rust `policyd` does not fix this by itself). No network listener (Unix socket only). | Hardened — residual: separate OS user/container still required for a real OS boundary; human review required | 2026-11-23 |
| R-007 | `run_command` (Level 3) can execute arbitrary binaries inside the token scope; an approval granted for one benign command could be replayed for a different command if approvals are scoped too broadly | High | Medium | Approvals are now scoped to (token_id, tool_name, permission level, argument hash) — a different level or different arguments needs a fresh approval (ADR-005). Only the argument hash is stored and audited, never raw args. Approvals still expire after 600s by default and are denied while tainted; `run_command` blocks sudo/su/doas and `rm` as argv[0]. | Fixed 2026-11-23 (security-fixes round, commit `57778fe` (PR #5)); human review required | 2026-11-23 |
| R-008 | Audit log hash chain detects tampering only if the verifier runs; an attacker who can write the log can also rewrite the whole chain from scratch (no external anchor) | Medium | Low | Hash chain + append-only file; Phase 1 `audit verify` detects in-place edits. External anchoring (signed checkpoints, remote copy) is deferred to a later phase and must be added before audit logs are relied on for forensics. | Open | 2026-11-23 |

| R-009 | `cli/_fallback.py` (933 lines) duplicates the policy engine and tool registry so the CLI can run without the real modules; two policy implementations can diverge, and the fallback runs in-process (weaker isolation than `policyd`) | Medium | Low | File deleted in the 2026-11-23 security-fixes round (commit `57778fe` (PR #5)); `cli/_compat.py` loaders now fail loudly (`PolicyUnavailable`/`RuntimeUnavailable`, CLI exit 2) when a real module is missing, and `pyproject.toml` already lists `core`, `policy`, `tools`, `adapters`, `cli` as installed packages. Tests assert the file is gone and the CLI errors clearly with core modules blocked. | Fixed 2026-11-23 (security-fixes round, commit `57778fe` (PR #5)) | 2026-11-23 |

| R-014 | Capability tokens carried a `network` flag that was never enforced, so a token issued without network access could still run a network call (e.g. `run_command` with `curl`) | High | Medium | Tools now declare a static `network` capability (only `run_command`) and `tools.definitions.is_network_call()` classifies each call from its argv (curl/wget/ssh/scp/git fetch…); the policy engine denies network calls on tokens with `network=False` (default — fail closed), audit-logged, and `policyd` re-classifies every check itself so a caller cannot downgrade a network call. CLI: `token issue --network`, `tool run --network`, `policy check --network` (ADR-006). Honest limit: argv classification is not a sandbox — arbitrary code via `run_command` (e.g. `python3 -c` using urllib) can still reach the network, which is why the tool stays Level 3 and approval-gated. | Fixed 2026-11-23 (security-fixes round, commit `57778fe` (PR #5)); ID assigned in that round — the flag previously had no risk ID | 2026-11-23 |
| R-010 | CLI-model provider inherits the parent process environment, so a compromised CLI binary could read ambient credentials (e.g. API keys in env) even though the gateway never passes secrets explicitly | High | Low | Child environment is now built from an allowlist only (`CLI_ENV_ALLOWLIST` in `core/cli_providers.py`: PATH/HOME/TMPDIR/locale/TERM/USER, secret-like names dropped), PATH forced to pinned dirs + default system dirs; explicit per-call `env` overrides (operator opt-in) still pass through (ADR-009). | Fixed 2026-11-23 (risks round, R-010–R-013) | 2026-11-23 |
| R-011 | `CliProviderError` includes up to 200 chars of CLI stderr, so a hostile CLI could echo sensitive data into an error that gets logged | Medium | Low | CLI stderr is passed through `redact_secrets()` (key=value assignments, Bearer tokens, sk-/sk-ant-/ghp_/AKIA/xox* shapes, PEM blocks) before entering the exception; exit code kept (ADR-009). | Fixed 2026-11-23 (risks round, R-010–R-013) | 2026-11-23 |
| R-012 | CLI `ping()` only checks the binary resolves on PATH, not that it is the genuine binary — a fake `opencode` earlier on PATH wins (PATH spoofing) | High | Low | Bare CLI names resolve only against pinned dirs: per-provider `cli_binary_dirs` > `OPENCOBOT_CLI_BIN_DIRS` env var > `/usr/local/bin:/usr/bin:/bin`; ambient PATH never consulted for resolution, gateway `ping()`, or the child PATH (ADR-009). Absolute paths still need an allowlisted basename + executable bit. | Fixed 2026-11-23 (risks round, R-010–R-013) | 2026-11-23 |
| R-013 | Web UI `?token=` query-param auth puts the daemon token in browser history / server logs (localhost-only, token never leaves the machine) | Medium | Medium | `?token=` auth, token-carrying redirects and hidden token form fields removed. Browsers sign in once via `POST /login` (token in body only) and get a random session id in an HttpOnly, SameSite=Lax `opencobot_session` cookie (12h sliding, in-memory store, `POST /logout` invalidates); API clients use Bearer / `X-OpenCobot-Auth` headers (ADR-009). | Fixed 2026-11-23 (risks round, R-010–R-013) | 2026-11-23 |
| R-015 | PowerShell execution policy on the Windows host (machine/user/GPO) can interfere with running `powershell.exe`, or a locked-down policy can break the adapter's PowerShell calls (`list_windows`, `run_powershell`) | Medium | Medium | The adapter invokes `powershell.exe -NoProfile -NonInteractive -Command` (a command string, not a script file), which avoids script-file policy; verify the effective policy during laptop testing (`Get-ExecutionPolicy -List`) and document what is required. Do not weaken the host policy to make OpenCobot work. | Open — verify on laptop (Phase 3) | 2026-11-23 |
| R-016 | PATH spoofing on Windows: `git.exe` / `powershell.exe` are resolved via `shutil.which`, so a malicious binary earlier on PATH (or a planted `git.exe` / `powershell.exe`) wins and runs with the agent's privileges | High | Low | `shutil.which` lookup is explicit about the Windows binary name (`git.exe` checked first); document that PATH must be trusted; consider pinning absolute paths in config in a later phase (same residual as R-012 for CLI providers). | Open — Phase 3, documented in ADR-008 | 2026-11-23 |
| R-017 | Named-pipe IPC without an ACL: any local process could connect to `\\.\pipe\opencobot-policyd` / `\\.\pipe\opencobot-daemon` and issue policy decisions or daemon commands (SECURITY.md adversary 5) | Critical | Medium | `ctypes` `CreateNamedPipeW` listener landed (ADR-010, branch `agent/wf-namedpipe-acls`): DACL denies `NT AUTHORITY\NETWORK` (S-1-5-2) and grants read+write only to the current user SID and `BUILTIN\Administrators`; every other local account gets no ACE. Fail closed is kept: any ACL-build or pipe-creation failure refuses to start, never serves an ACL-less pipe. Mock-verified on Linux (20 tests in `tests/test_windows_pipe_server.py`: DACL policy, struct layouts, accept loop, fail-closed paths, policyd/daemon wiring). | Implemented, mock-verified — awaiting live verification on a Windows laptop (docs/WINDOWS_TESTING.md §6); human review required | 2026-11-23 |
| R-018 | UI Automation / screenshot trust boundary: a future Windows screenshot or UI Automation path would let the agent see (and act on) every window, including password managers and banking, before any image leaves the machine | High | Low | Deferred, not implemented: `screenshot_available()` honestly returns `(False, reason)` and is never faked. When UI Automation lands, it must follow ARCHITECTURE.md §5 screen privacy (block/blur sensitive windows) and get human review first. | Open — deferred (Phase 3) | 2026-11-23 |
| R-019 | `wmic` is deprecated and removed from newer Windows builds, so `system_info` (edition, RAM) degrades to `None` on hosts without it | Low | Medium | Every `wmic` call in the Windows adapter is guarded — a missing `wmic` yields `None` for that field instead of crashing. Later step: prefer CIM / `Get-CimInstance` via PowerShell. | Open — Phase 3 | 2026-11-23 |

Phase 1 status (2026-11-23): R-001 is mitigated in code by taint tracking (Level 3+ locked while tainted) and the red-team suite in `evals/redteam.py`; R-003 is mitigated by `verify()` on every tool. Both still require human review of `policy/` before merge.

Phase 2 status (2026-11-23): R-005 is now enforced in code by the gateway routing table (secret = local-only, unknown label fails closed) plus the benchmark/CLI paths; R-010–R-013 are new Phase 2 risks, documented above.

Risks-round status (2026-11-23): R-010–R-013 are now Fixed in code (ADR-009) — scrubbed CLI environment, redacted CLI stderr, pinned binary dirs, session-cookie web UI auth — with 27 new tests in `tests/test_r010_r013.py`.

Security-fixes status (2026-11-23): the four deferred Phase 1 follow-ups are now done — R-007 approvals are level-scoped and argument-bound (ADR-005), the token `network` flag is enforced (R-014, ADR-006), R-009 `cli/_fallback.py` is deleted, and R-006 is hardened (0700/0600 permissions enforced on startup, `doctor` reports the boundary honestly). R-006's residual — a real OS boundary still needs `policyd` under a separate OS user/container — is open by design, not by omission.

Windows-adapter status (2026-11-23, Phase 3, branch `agent/windows-adapter`): the Windows adapter, per-call OS dispatch, PowerShell `run_command` path and named-pipe client transport are implemented and mock-verified on Linux (80 Windows tests: 46 adapter + 17 transport + 17 wiring); nothing is live-verified on Windows yet. New risks R-015–R-019 (ADR-008). The named-pipe server no longer fails closed for lack of an implementation: the `ctypes` ACL listener landed on branch `agent/wf-namedpipe-acls` (ADR-010, R-017 — DACL: current user + Administrators only, NETWORK denied; 20 more mock tests), so end-to-end `tool run` / `daemon start` / `doctor` on Windows are unblocked pending the laptop run — see [docs/WINDOWS_TESTING.md](WINDOWS_TESTING.md) §6 for the listener verification steps and what "pass" means per step.
